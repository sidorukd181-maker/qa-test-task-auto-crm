## 1. Предполагаемые требования к форме регистрации

Так как в условии не было готового макета и ТЗ, за основу я взяла страницу регистрации зарубежной автомобильной CRM-системы (финская версия Auto CRM).
<img width="950" height="475" alt="{8EFD1620-1C02-4BD4-B48B-25CF7F80FDB7}" src="https://github.com/user-attachments/assets/f4fd22c1-5a45-4700-987d-628c9ef53503" />

Для написания чек-листа я опиралась на эти базовые минимальные предположения о форме:
1.	На странице 6 полей — Название организации, Название выставочного зала, Имя, Фамилия, Email и Пароль. Все поля обязательны для заполнения.
2.	Система одновременно создает аккаунт администратора, профиль компании и первый салон при успешной регистрации. Создать два аккаунта на один и тот же email нельзя, email должен быть уникальным
3.	Для названий организации и выставочного зала (2–255 символов) разрешены кириллица, латиница (и их смешивание), цифры, пробелы и некоторые спецсимволы («»", -, ., ,, (), №, &). Запрещены эмодзи, переносы строк и знаки (<, >, ;, {, }).
4.	Для имени и фамилии (1–50 символов) разрешены только кириллица или только латиница, разрешены дефис, апостроф и пробел для двойных имен/фамилий. Запрещены цифры и спецсимволы (!, @, #, $, *, _, ?, \, /).
5.	Для email разрешена только латиница, цифры, точки (не в начале и не рядом с @) и разрешенные спецсимволы в префиксе (!#$%&'*+-/=?^_{|}~). Запрещены кириллица, пробелы, двойные @ 
6.	Минимальная длина пароля – 8 символов, максимальная - 64, есть иконка «глаз» для просмотра. Пароль должен содержать заглавную букву, строчную букву, цифру и спецсимвол. 
7.	Пробелы в начале и в конце текста система должна автоматически отрезать

*(В реальной работе все эти детали я бы предварительно уточнила у аналитика или менеджера проектов).*

## 3. Тест-кейсы страницы аутентификации

### TC-001: Успешная аутентификация пользователя с валидными учетными данными
 **Приоритет:** Critical

**Предусловия:** Пользователь уже зарегистрирован в системе 

**Тестовые данные:**
  * Электронная почта: `darsi@mail.ru`
  * Пароль: `Pass146;)`

| № | Шаг | Ожидаемый результат |
| :--- | :--- | :--- |
| 1 | Перейти на страницу `https://stellantis.autocrm.ru/` | Отображается форма входа, поля «Электронная почта», «Пароль» и кнопка «Войти» активны и доступны для взаимодействия |
| 2 | Ввести в поле «Электронная почта» валидный email из тестовых данных | Введённый email отображается в поле, поле выделяется зеленым цветом, ошибок валидации нет |
| 3 | Ввести в поле «Пароль» валидный пароль из тестовых данных | Введённый пароль отображается в поле в замаскированном виде, поле выделяется зеленым цветом, ошибок валидации нет |
| 4 | Нажать кнопку «Войти» | Выполняется вход в систему, пользователю становится доступен основной интерфейс управления CRM |

### TC-002: Попытка аутентификации пользователя с неверным паролем
**Приоритет:** High
  
  **Предусловия:** Пользователь с адресом электронной почты `darsi@mail.ru` существует в системе
  
  **Тестовые данные:**
  * Электронная почта: `darsi@mail.ru`
  * Пароль: `errorERROR123`

| № | Шаг | Ожидаемый результат |
| :--- | :--- | :--- |
| 1 | Перейти на страницу `https://stellantis.autocrm.ru/` | Открывается страница входа |
| 2 | Ввести в поле «Электронная почта» валидный email из тестовых данных | Введенный email отображается в поле «Электронная почта», поле выделяется зеленым цветом |
| 3 | Ввести в поле «Пароль» неверный пароль из тестовых данных | Введенный пароль отображается в замаскированном виде в поле «Пароль», поле выделяется зеленым цветом |
| 4 | Нажать кнопку «Войти» | Вход в систему не выполняется, появляется сообщение об ошибке «Некорректный email / пароль» |

## 4. Баг-репорты страницы аутентификации

### BUG-01: CRM Stella: Кнопка «Войти» остается заблокированной после исправления некорректного логина
 **Критичность:** Major
 
 **Окружение:** Windows 11 IoT Корпоративная (Вер. 22H2, Сб. 22621.4602), Google Chrome 155.0.8059.80 (64-bit)


**Шаги воспроизведения:**
1. Перейти на страницу входа `https://stellantis.autocrm.ru/`
2. Ввести в поле «Электронная почта» некорректное значение (например, `darsimail.ru` без `@`)
3. Ввести в поле «Пароль» валидное значение (например, `Password123`)
4. Нажать кнопку «Войти»
5. Исправить значение в поле «Электронная почта» на валидное (`darsi@mail.ru`)
6. Проверить состояние кнопки «Войти»

 **Фактический результат:** После ввода некорректного email кнопка «Войти» блокируется и остается неактивной даже после исправления адреса на валидный. Продолжить авторизацию можно только после перезагрузки страницы и повторного ввода всех данных (см. вложение 1.mp4)
 
 **Ожидаемый результат:** После исправления email на валидный кнопка «Войти» становится активной и доступной для нажатия

### BUG-02: CRM Stella: Placeholder'ы полей формы не переводятся при переключении языка на английский
 **Критичность:** Minor
 
 **Окружение:** Windows 11 IoT Корпоративная (Вер. 22H2, Сб. 22621.4602), Google Chrome 155.0.8059.80 (64-bit)

**Шаги воспроизведения:**
1. Перейти на страницу входа `https://stellantis.autocrm.ru/` (по умолчанию отображается на русском языке).
2. Нажать на переключатель языка «ENG» в правом верхнем углу.
3. Проверить отображение placeholder'ов внутри полей ввода.


 **Фактический результат:** При переключении языка интерфейса с русского на английский основные элементы формы переводятся, но placeholder'ы полей «Электронная почта» и «Пароль» остаются на русском языке («Введите логин», «Введите пароль») (см. вложение 1.png)
 
 **Ожидаемый результат:** Весь текст страницы входа, включая подсказки внутри полей (placeholder), переводится на английский язык («Enter login», «Enter password»).
